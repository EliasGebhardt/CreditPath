# CreditPath — Millennium X · Team 3

**A clickable student prototype for SME financing guidance.**

This concept explores how a busy SME owner can find a suitable financing path using existing account context and transparent, personalised explanations. It is **not** an official Millennium bcp product or website.

## Live demo

Once GitHub Pages has been enabled, find the published URL in **Settings → Pages**.

## What you can try

1. Open the **Início** dashboard and hover the forecast points to see the projected cashflow values. Click the highlighted financing opportunity.
2. Open **Créditos** in the left navigation; the usual credit offerings appear in the right-hand panel, with CreditPath highlighted at the top.
3. Enter CreditPath, use the fictional financial context or add an extra outgoing payment or incoming receipt, and see one **illustrative** recommendation with transparent reasoning.
4. Explore the cashflow and project simulation entry points.

The prototype is a single HTML file (`index.html`) with embedded CSS and JavaScript; no framework, build step or server is needed. Open `index.html` directly in a browser or serve the folder through a static web server.

## Team development

- **Small fixes:** edit `index.html` directly on a branch or in GitHub's web editor.
- **Larger changes / Codex:** clone the repository, make a branch, and open a Pull Request. Please test the main navigation, chart hover, send button and recommendation before merging.
- **Bug reports:** create a GitHub Issue with reproduction steps, expected behaviour and a screenshot.
- **Collaborators:** repository administrator can grant team members access via **Settings → Collaborators and teams**.

For GitHub Pages, select **Settings → Pages → Deploy from a branch → main / (root)** and save.

## Demo boundaries

- All company records, balances, receivables and credit recommendations are **fictional**.
- This is a **rule-based simulation**, not a live LLM, regulated credit advice or bank credit decision.
- The prototype does **not** use credentials, payment details, account connections, bank APIs or real user information.
- Do not upload transcripts or private bank materials to a public repository.
- Live lending rules, product suitability, commercial logic and regulatory checks would require bank ownership and validation before production use.
